애니메이션은 "조금 움직이고 → 그리고"를 1초에 수십 번 반복해서 만듭니다. 브라우저는 requestAnimationFrame으로 다음 화면 갱신 직전에 콜백을 불러 주는데, 이 반복을 렌더 루프라고 합니다. Three.js에서는 renderer.setAnimationLoop(fn)을 씁니다.

문제는 이 콜백이 얼마나 자주 불릴지 기기마다 다르다는 것입니다. 60Hz 모니터에서는 초당 60번, 144Hz 게이밍 모니터에서는 144번, 느린 폰이나 무거운 장면에서는 20~30번만 불립니다. "프레임마다 0.02라디안 회전"처럼 짜면 144Hz 화면에서는 2.4배 빨리, 느린 폰에서는 느리게 돕니다.

해결책은 지난 프레임 이후 흐른 시간(deltaTime, 초)을 곱하는 것입니다. "초당 1.2라디안"으로 정의하면 FPS와 관계없이 같은 속도가 됩니다.

let last = performance.now();
renderer.setAnimationLoop((now) => {
  const dt = Math.min((now - last) / 1000, 0.1); // 초 단위, 탭 전환 후 큰 점프 방지
  last = now;

  frameCube.rotation.y += 0.02;      // ✗ FPS에 따라 속도가 변함
  timeCube.rotation.y  += 1.2 * dt;  // ✓ 항상 초당 1.2 rad

  renderer.render(scene, camera);
});

이 사이트의 모든 데모는 화면 밖으로 나가면 루프가 그리기를 멈추고, 멀리 벗어나면 렌더러까지 해제합니다. 루프는 계속 돌아가는 비용이기 때문입니다.

해볼 것

  • FPS 제한을 15로 바꿔 보세요. 왼쪽 큐브는 1/4 속도로 느려지고, 오른쪽 큐브는 뚝뚝 끊기지만 같은 속도를 유지합니다.
  • "144Hz 모니터 흉내"를 고르면 왼쪽 큐브가 과하게 빨라집니다.
