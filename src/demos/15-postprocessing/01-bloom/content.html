Three.js의 EffectComposer는 패스(pass)를 순서대로 이어 붙이는 파이프라인입니다. 각 패스는 앞 패스의 결과 이미지를 입력으로 받아 새 이미지를 만듭니다.

const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));        // 1) 씬을 텍스처에
composer.addPass(new UnrealBloomPass(size, 1.2, 0.5, 0.8)); // 2) 밝은 부분 번지기
composer.addPass(new ShaderPass(VignetteShader));       // 3) 가장자리 어둡게
composer.addPass(new OutputPass());                     // 4) 톤매핑 + sRGB 변환

// 렌더 루프: renderer.render(...) 대신
composer.render();

블룸(Bloom)은 어떻게 만드나

  1. 밝은 부분 추출: 밝기가 threshold를 넘는 픽셀만 남깁니다.
  2. 흐리기: 그 이미지를 해상도를 반씩 줄여 가며 여러 단계로 블러합니다(다운샘플 체인). 작은 이미지를 흐리는 것이 싸고 넓게 번지기 때문입니다.
  3. 더하기: 흐린 결과를 원본 위에 strength만큼 더합니다. radius는 단계들을 섞는 비율로, 번짐의 넓이를 정합니다.

블룸이 자연스러우려면 장면이 1.0보다 밝은 값(HDR)을 가져야 합니다. 그래서 렌더 타깃을 HalfFloatType으로 두고, 네온은 emissiveIntensity를 1보다 크게 설정합니다. 톤매핑은 마지막 OutputPass에서 한 번만 적용합니다. 순서가 바뀌면 이미 0~1로 눌린 값으로 블룸을 계산해 번짐이 약해집니다.

후처리 패스마다 화면 전체 픽셀을 한 번 더 처리하므로 해상도가 높을수록 비쌉니다. 모바일에서는 패스 수를 줄이거나 렌더 타깃 해상도를 낮춥니다. 또 렌더 타깃에 그리면 기본 안티앨리어싱이 사라지므로, 이 데모는 MSAA 렌더 타깃(samples: 4)을 씁니다.

해볼 것

  • threshold를 0으로 내리면 바닥까지 전부 번져 뿌옇게 됩니다. 1.0 이상으로 올리면 HDR로 밝은 네온만 빛납니다.
  • "발광 세기"를 1 아래로 낮추면 threshold를 넘지 못해 블룸이 사라집니다.
  • RGB 분리와 필름 그레인을 켜면 레트로 VHS 느낌이 납니다. 각각 셰이더 하나짜리 패스입니다.
